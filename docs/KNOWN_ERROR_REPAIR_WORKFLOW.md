## 固定分母与证据

- 从冻结基线逐条重建全部 FP、FN；同一业务问题可能同时产生一条 FP 和一条 FN，两种事件分别留痕。关联诊断不擅自合并或删减分母。
- 报告旧 FN 找回数 / 全部旧 FN、旧 FP 消除数 / 全部旧 FP，以及明确注明双事件计数的综合修复率。原始严格 P/R/F1 作为伴随指标，不替代用户选择的修复率目标。
- 未执行、执行失败、待裁定、缺证据均不得算作已修复；部分批次的通过率不得冒充全部错误修复率。
- FP 的“已消除”不能仅由候选 ID、措辞或跨度变化决定，必须关联同一处问题的当前输出与评分证据。定位不可靠的记录保持未解决。
- 同时列出当前新增 FP、原本命中而现在漏掉的错误、执行覆盖和预算。只删掉输出不构成合格修复。
- 严格评分不变；标注争议另行记录，不静默修金标、放宽包含规则、扩大类型别名或排除难例。
- 基准匹配与业务判断区分记录。公开标注未匹配提示不自动证明真实业务误报；待查来源不得臆断。

## 混合迭代工作流

1. 对全部旧错误建立事件账本，按机制分组，保留原始候选、金标、原文位置及关联关系。
2. 先用规则诊断、归档候选回放和必要的正反例测试定位确定性缺陷；这些结果明确标记为非端到端模型结果。
3. 修改实际 `detect_text` 流程的通用节点；不根据文档 ID 返回答案，不将旧金标放入推理提示。
4. 冻结本批源码和配置，使用真实模型对该批错误所在文档的全文回测。按需要合并同篇多个错误，以减少重复调用。
5. 独立评分并记录每一旧事件的修复前后证据、剩余问题和新增副作用；据此选下一批修改。
6. 最终必须覆盖全部旧错误，并在同一候选版本下有可验证的回测结果，才能宣称达到 95%。跨版本拼接各自最好结果不能作为最终达标证明。

输入一份研报草稿 PDF 和对应的财报 PDF，输出错误位置、错误类型、原文、依据与修改建议。

本仓库用于 2026 年北京市金融人工智能比赛的参赛作品开发，五人并行推进，各模块独立可跑、
按统一字段对接。当前进度以 `docs/` 下的记录与实际代码为准。

## 最小可交付范围

输入研报草稿 PDF 与对应财报 PDF，输出：

1. **错误位置**：文件 → 页码 → 区块坐标，可高亮回原文；
2. **错误类型**：数值、单位、期间、口径、引用等分类；
3. **原文与依据**：研报原句 + 财报/公告中的对应证据；
4. **修改建议**：建议替换内容与修改原因；
5. **结果分级**：已确认错误 / 待人工确认 / 未发现问题。

### 评测指标

以下为原项目业务目标，尚不代表第二版实测达标。FinED-Bench 公开文本按错误实例评分，业务配对按声明核查，两套分母分别报告；不将小样本配对分数外推到全部金融文档。价格、核查覆盖率、不确定性与复核效率按 `evals/README.md` 口径记录：未计时的复核不当 0 秒，可自动判断却转人工与证据不足却强判分开统计。

| 类别 | 指标 | 统计方法 | 目标 |
| --- | --- | --- | --- |
| 准确度 | 判错精确率 | 正确识别的错误数 ÷ 系统报出的错误数 | ≥ 90% |
| 准确度 | 错误召回率 | 正确识别的错误数 ÷ 测试集已知错误数 | ≥ 80% |
| 准确度 | 正确内容误报率 | 误判的正确项数 ÷ 正确内容总数 | ≤ 10% |
| 准确度 | 类型准确率 | 定位命中中错误类型与标注一致的比例 | 逐批报告 |
| 抽取指标 | 抽取覆盖 | 正确抽取的唯一声明 ÷ 应核查声明（人工标注） | 逐批报告 |
| 抽取指标 | 确定性结论 | 有明确自动结论（已确认/未发现）的声明数及占比 | 与转人工分列报告 |
| 抽取指标 | 转人工数量 | 无自动结论、留给人工复核的声明/候选数及占比 | 与确定性结论分开报告 |
| 核查覆盖率 | 核查范围覆盖 | 进入核查的声明数 ÷ 应核查声明；页级 ok/warn 覆盖比例；失败页单列 | 逐批报告，不缩小分母 |
| 不确定性处理 | 过度转人工率 | 可自动判断却转人工的声明 ÷ 可自动判断声明 | 越低越好，逐批报告 |
| 不确定性处理 | 证据不足强判率 | 证据不足却给出确定结论的条数 | 0，否则逐条列示 |
| 证据支持度 | 证据定位准确率 | 正确定位来源及页码的比例 | ≥ 90% |
| 证据支持度 | 证据语义支持率 | 引用证据确实支持该结论的比例（人工审核，公开字符锚点不替代外部证据） | 逐批报告 |
| 人工复核效率 | 单条/单篇复核耗时 | 实测开始到保存的墙钟时间；未计时条目单列，不当 0 秒 | 逐批报告 |
| 人工复核效率 | 待复核队列规模 | 待复核提示按错误类型与优先级分级统计 | 逐批报告 |
| 可靠性与运行速度 | 计划/尝试/完成文档数 | 失败原因分类记录，失败保留在完整分母 | 逐批报告 |
| 可靠性与运行速度 | 耗时 P50/P95 | 单文档运行时长分位数 | 逐批报告 |
| 可靠性与运行速度 | 重复一致性 | 同输入复跑结果一致比例（需另行复跑验证） | 报告 |
| 价格 | API 费用 | 调用及重试的 token、价格来源与日期、共享账本保守预留 | 预算授权内，账本延续不新建 |
| 价格 | 人工成本 | 实测复核人时与 API 费用分开列示 | 逐批报告 |
| 建议完整性 | 建议完整性 | 已确认错误均包含定位、原文、依据、建议 | 逐条检查 |

### 第 1 步：解析

## 给下游的接口约定

| 对接方 | 我提供什么 | 格式 | 约定 |
| --- | --- | --- | --- |
| C 核查逻辑 | 页级块级解析结果 + 质量报告 | `parse_result.json`、`blocks.jsonl` | 只引用 `ok`/`warn` 页；引用必须带 `page` 与 `bbox` |
| D 前端与导出 | 原文高亮参数 | 页码、坐标、页面尺寸 | 左上角原点、单位为点，按渲染缩放换算 |
| E 测试与交付 | 质量表与失败清单 | `quality_summary.csv` | 逐页状态与原因可直接作为测试记录 |

字段要点：每个区块包含 `block_id`、`type`、`bbox`、`order`、`text`；
表格额外含 `cells`（行列号 + 单元格坐标），文本块含 `sentences`（句级坐标），
图片与表格块含 `caption` 与 `source_note`（图表标题与资料来源）。

## 协作约定

1. **原始数据不进仓库**：研报 PDF、财报 PDF 只放本地 `data/`，仓库只保留代码与文档。
2. **密钥不进仓库**：模型端点密钥一律用环境变量，配置模板见 `pdfparse/deploy/ov.conf.example`。
3. **第三方成果如实登记**：新增依赖或模型时同步更新 `pdfparse/THIRD_PARTY.md`。
4. **接口字段改动要同步 A**：字段表由 A 冻结，改动先在任务看板提出。
5. **推送方式（重要）**：本机网络连不上 `github.com:443`，`git push` 会失败，改用
   `py -3 tools/push_via_api.py`。它按本地 HEAD 重建远端分支，所以**新上传的内容会覆盖之前的**；
   推送前请先确认队友的提交已经合并到本地，避免覆盖别人的工作。

```bat
git add -A
git commit -m "说明这次改了什么"
py -3 tools/push_via_api.py
```

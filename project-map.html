02 · FinED-Bench 如何进入第二版

本轮学习的正确论文是 Are Large Language Models Reliable Reviewers? A Benchmark for Error Detection in Financial Documents。本地原文为 2026.findings-acl.1481.pdf。FinRiskAtlas 是另一篇论文，其操作级工具仅作旧的可选分析。

保留结构和原文偏移

独立入口 yjcheck.text_review.detect_text() 接收正文字符串。能容纳时整篇处理；超限采用段落窗口并保留邻接上下文，不静默截断。

同时检查 15 类错误，生成候选

模型提示使用完整可见上下文和少量开发集示例；当前待测文档不能成为自己的示例。规则覆盖的类型有限，15 类分类空间不代表全部规则能力已实现。

定位原句，再核验可复算证据

组合流程校验原文引用及字符区间，Decimal 验证可支持的计算；跨窗口补查使用已知指标的原始句子。其他语义候选保持待复核，非法锚点留存拒绝原因。

单独展示结论和未处理范围

输出 errors / coverage / traces；允许空错误列表。规则运行、模型运行与全局补查完成分别记录。空结果不代表全文正确。

独立文本页面

上传 UTF-8 TXT/Markdown 或粘贴原文，默认离线，可显式启用模型。用字符区间定位；不生成不存在的页码。

frontend/text_review_view.py

配对流程的补充

研报与财报照常核查，结果新增独立 text_review；前端“文本补充检查”单列候选和规则确认数，不混入传统核查分母。

factcheck/src/yjcheck/pipeline.py
工程补充不是论文结论：确定性验证、原文锚点、长文索引及预算账本是本项目方案，仍需通过同模型对照评价。重复已知指标索引不等于任意实体关系都已覆盖。

种子 20261003；标准集 973 篇、长文 24 篇。4,178 个原始错误中 4,093 个可评分，85 个保留排除审计。按可识别来源分组，重复文本不跨集合；未知公司不能假装已经识别。

答案与样本分开

dataset_prepare.py 保存源文件哈希、划分与定位审计；推理 run_v2.py run 只读 inputs 与开发示例，另一个 score 进程才读 gold。禁止模糊修复自动成为精确答案。

对照与预算

冻结旧版规则 → 同一模型直接检测 → 组合流程。每篇各组依次运行，先试 10 篇；按用户授权，共享账本累计上限已按两次授权提高到 100 元，保留历史费用。续跑绑定配置与源码指纹；缺少价格/上下文或超过已核验费率有效期时不发真实请求。

评分分母完整

错误实例采用原句匹配/包含且类型一致的一对一匹配，多片段作为一个错误。漏预测计漏检，重复不重复得分，分类准确率独立计算。这是依据论文描述的项目实现。

公开文本与业务配对分报

公开集测文本检测；配对材料另测 PDF 解析、外部证据、定位、自动判断和复核耗时。16 条正常候选已打包待人工签核，不能当作已验证负例。

04 · 从“开始核查”追到实际代码

用户上传 → 保存文件

frontend/app.py → settings_panel() / save_upload()，上传文件按内容哈希前缀组织目录。

页面调用核查总入口

execute_check() → yjcheck.pipeline.run_check()，传入研报、来源文件、公司、引擎和可选模型配置。

加载材料并统一文档对象

adapters.load_document() → Document；PDF 进入解析流水线，DOCX 走段落抽取，预解析 JSON 走解析结果适配。随后 bind_company() 对齐公司身份。

生成待查声明与可信来源

check_documents() → extract_claims(report) + 研报表格事实；财报由 extract_source_facts() 抽取，可选模型候选也在此合入。

外部比对 + 研报内部一致性核查

check_facts(claims, source_facts) 与 check_intrinsic_consistency(report, claims) 合并为 findings；文件身份或完整性阻断问题会把结论转为待人工确认。

落盘 → 配对结果与文本补充

write_result() 保存核查产物；页面展示概览、结果列表、证据对照、人工复核、导出、助手问答，以及独立的文本补充检查。

架构观察：frontend 是 Python / Streamlit 页面，直接导入本地 yjcheck 和 yjparse；这条主链没有独立 HTTP 后端服务。

05 · 模块之间传的是什么？

对象 / 文件核心内容为什么需要
parse_result.jsondoc、engine、pages、blocks、cells / sentences、quality_report保存原始文字与页面定位；解析层不负责财务单位换算或判错。
Document / Fact公司、指标、value、unit、period、basis、scope、evidence把正文与表格转成能按相同维度比较的事实。金额 value 用十进制字符串。
check_result.jsonsummary、documents、findings、source_facts、model_traces每条发现关联 claim、evidence、rule_id、calculation 和修改建议。
text_reviewerrors、原文 spans、验证状态、coverage、运行 traces文本候选独立存放；不伪装成外部财报证据，不虚构 PDF 页码。
manifest.json核查 run_id + JSON / CSV / Markdown 的 SHA-256检查三份核查产物是否被修改或混用。
review.json按 finding_id 保存状态、备注、复核人、历史及显式计时时长把人工意见单独保存，保留原始核查产物的哈希。
assistant_traces.jsonl助手请求与结果留痕追踪模型解释过程；核查抽取另有 model_traces。

06 · 跟着一个数字走一遍

以下是教学示例，用来解释代码中的单位归一化、显示精度与证据准入逻辑；不是对真实文件的核查结果。

来源事实：示例公司，2025H1，合并口径营业收入 15,000 万元，证据定位完整。

研报声明：同公司、同期间、同口径营业收入 1.60 亿元。

程序使用 Decimal，并按研报显示的小数位进行 ROUND_HALF_UP。只有相关维度与证据满足条件后，数值比较才有意义。


07 · 建议按这个顺序读代码
第一轮 · 抓主线
  1. frontend/app.py：先读 execute_check() 和 main()。
  2. factcheck/src/yjcheck/pipeline.py：读 run_check() → check_documents() → write_result()。
  3. factcheck/src/yjcheck/models.py：理解 Document / Fact / Finding / Evidence。
第二轮 · 理解判定
  1. adapters.py：输入怎样变成可信文档。
  2. claim_extract.py / source_extract.py：正文与财务表格怎样变成事实。
  3. rules.py：从 normalize()、_rounded_expected()、_check() 入手。
  4. intrinsic.py：了解研报内部一致性核查。
  5. text_review.py / text_context.py：文本候选、长文覆盖和确定性验证。
  6. model_runtime.py：共享预算、费用预留和失败留痕。
上述文件都在 factcheck/src/yjcheck/。

阅读 frontend/ 的 highlight.py、review_store.py、exports.py、assistant.py，然后看 factcheck/tests/ 与 pdfparse/tests/ 中对应边界用例。

08 · 阅读项目时要分清的现状
代码中已经有
  • 上传研报与多个来源文件、执行核查。
  • 配对结果七个视图、独立文本入口、证据高亮、复核计时。
  • CSV、Markdown、JSON 导出；PDF 导出依赖可用时启用。
  • 模型辅助抽取和结果解释，两者都有离线路径。
能力边界与学习重点
  • complete=true 只覆盖已抽取的受支持事实，不代表全文无错。
  • 失败页不可作为有效数值证据；适配层还会复验哈希、页数和坐标。
  • 来源冲突或口径缺失进入人工确认，不能随意挑一个数字。
  • 助手数值检查会标记异常；报告问答中异常数字会产生提醒，不能视为模型输出都已被强制纠正。
本轮实测边界：本次 200 篇是开发阶段实验／阶段性验证，没有训练或微调模型权重；已经执行 DeepSeek V4.1 Flash 推理和评分，最终独立能力测试尚未进行。历史 eval_oct05 划分名与运行时冻结配置保留。各组均尝试 200 篇，三组共同成功完成 199 篇，1 篇 transport_timeout 未重试，失败仍在分母中。直接模型 P/R/F1 为 60.39%/65.28%/62.74%，组合为 59.96%/65.77%/62.73%，没有总体 F1 提升；89 篇研报 F1 分别为 67.45%/67.34%。本批新增保守费用 8.719137 元，累计快照 13.571324 元、284 次调用，不是实时余额或独立样本数。当前进程均已退出，调用已停止；PR #2 已创建但有冲突、未合并队友主线。598 篇开发池做过小样本和离线验证，但未进行真实模型全量扩跑；199 篇最终保留集未用于推理及最终测试。工程单元测试和前端联调已执行，不能替代最终能力测试；前期小样本也不能被省略成“至今一共只用过 200 篇”。参阅 阶段实验与交接边界、200 篇阶段实验报告 与 公开汇总计数。人审负例、语义证据支持与真人复核效率仍待验证。
当前助手的报告检索是对 findings 做关键词与中文片段匹配；解析模块另有知识库导出与检索能力，两者应分别理解。

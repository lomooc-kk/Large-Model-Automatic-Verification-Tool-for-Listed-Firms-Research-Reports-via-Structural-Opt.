# C 接入可靠性修复

本轮修复覆盖 2026-09-26 接入审查的八项主要问题及相关 UI、依赖问题。

- 文档 ID 由安全文件名与 SHA-256 前 16 位组成。同名不同内容不会覆盖；相同内容再次解析保留同一文档 ID，并产生新运行 ID。
- 每次产物保存在 `<out>/<doc_id>/runs/<run_id>/`，运行清单只校验此历史路径。文档目录顶层继续保存最新产物，兼容既有 CLI、报告、预览、KB 导出；`latest.json` 指向最新运行。
- 从原始 PDF 独立读取页数与页面尺寸。缺页生成失败占位页，重复和越界页号保留失败信息；`doc.total_pages` 始终表示原始 PDF 页数。C 必须检查页面状态，空占位页不构成证据。
- OCR 合并保留换行，并检查横向重叠，避免跨列数字拼接。OCR 页仍标为需复核。
- `fail` 页默认不进入 Markdown 正文和 KB 索引；离线检索再次排除失败页。完整诊断内容保留在解析 JSON 中。
- pdfplumber 直接遍历 `find_tables()` 列表，单元格坐标按 `table.rows[r].cells[c]` 取值。
- PyMuPDF 句子字符区间可直接切片 `Block.text`，句子文本可能包含原文换行。坐标仍为按行字符比例估计的高亮位置。
- 图表标题、来源按横向重叠和纵向距离关联；无法唯一匹配则保持未关联。
- 坐标裁剪后重新检查退化矩形并判为硬失败。`reference="none"` 真正关闭对照引擎。
- 上传文件按内容隔离；UI 证据缓存绑定文档、运行和页码，检索按钮键包含文档和页码；核心依赖显式声明 Pillow。

回归测试：`python -m unittest discover -s pdfparse/tests -v`。新增用例位于 `test_handoff_regressions.py`，覆盖真实 PDF 表格、句子偏移、同名文件及历史哈希，也覆盖缺页、OCR、拒绝页和多栏关联边界。可选 OCR、Streamlit 测试需安装 `requirements-engines.txt` 对应依赖。

这些检查证明解析接入边界被覆盖，不代表财务事实核查准确率；C 的业务验收由独立的核查测试与 E 样本评估承担。
